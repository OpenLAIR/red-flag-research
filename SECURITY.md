# Security policy

## Reporting a vulnerability

Please do not open a public issue for a security problem. Report it privately
in one of these ways:

- Use GitHub's private vulnerability reporting: on the repository's
  **Security** tab, choose **Report a vulnerability**.
- Email **red.flag.autoresearch@gmail.com** with "SECURITY" in the subject line.

Include what you found, where (file, commit or URL), and how to reproduce it.
We will acknowledge your report within 5 working days and tell you what we plan
to do.

## Exposed credentials or personal data

If you find an API key, token, password, private path or personal information
anywhere in this repository, its history, its releases or the benchmark files,
report it the same private way. We will revoke the credential, remove the data
and tell you when it is done.

## Wrong results about a paper

A result you think is wrong is not a security issue. If you are an author and
believe a result about your paper is wrong, email **red.flag.autoresearch@gmail.com**. We
will correct it right away, and we take the result off the live page and the
public data while we check.

## Supported versions

Only the latest release and the `main` branch receive fixes.
